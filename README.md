# Sales Assistant Agent

A persistent AI sales assistant API with cross-session memory, real tool use, and self-evaluation on every response.

## Memory Design Decision

**Why SQLite?**
For this assignment, SQLite provides zero-config persistent storage that survives Railway restarts (when mounted as a volume). The memory layer is fully abstracted in `app/memory/__init__.py` — swapping to Postgres requires only changing the `DATABASE_URL` environment variable. Swapping to Mem0 or Redis requires only modifying `MemoryStore` methods in that single file.

**At scale**, I would replace SQLite with:
- **Postgres** (via Railway's managed Postgres addon) for concurrent writes
- **pgvector** for semantic/embedding-based memory retrieval
- **Mem0** for automatic summarization of older context to control token costs

---

## Eval Design

Every `/chat` response includes a self-evaluation block generated by a second LLM call that scores the primary response on groundedness, relevance, and confidence.

**Limitations:**
- LLM self-scoring has a known optimism bias — models tend to rate their own responses highly
- Scores are not calibrated against human labels

**What I'd replace it with in production:**
- A dedicated eval model (e.g. `claude-haiku` fine-tuned on labeled eval pairs)
- RAG-based groundedness check: verify every claim against catalog embeddings
- Human feedback loop to continuously calibrate scores

## API Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| POST | `/chat/{user_id}` | Send message, get response + eval |
| GET | `/chat/{user_id}/history` | Full conversation history |
| DELETE | `/chat/{user_id}/memory` | Wipe user memory (GDPR reset) |
| GET | `/catalog` | Product/pricing catalog |
| GET | `/health` | Health check |

## Cross-Session Memory Demo

These two curl commands demonstrate memory persisting across separate API calls:

**Call 1 — Ask about Enterprise pricing:**
```bash
curl -X POST https://YOUR-RAILWAY-URL/chat/demo_user \
  -H "Content-Type: application/json" \
  -d '{"message": "What is your Enterprise plan pricing and does it include SSO?"}'
```

**Call 2 — Reference previous context (new session, same user_id):**
```bash
curl -X POST https://YOUR-RAILWAY-URL/chat/demo_user \
  -H "Content-Type: application/json" \
  -d '{"message": "Does the plan we discussed also include audit logs?"}'
```

The agent will recall from DB memory that Enterprise pricing and SSO were already discussed, and answer about audit logs in context — without the client re-sending any history.

## Local Setup

```bash
git clone https://github.com/YOUR_USERNAME/sales-assistant-agent
cd sales-assistant-agent
pip install -r requirements.txt
cp .env.example .env
# Add your ANTHROPIC_API_KEY to .env
uvicorn main:app --reload
```

API docs available at: `http://localhost:8000/docs`

## Deployment (Railway)

1. Push repo to GitHub
2. Go to railway.app → New Project → Deploy from GitHub
3. Add environment variable: `ANTHROPIC_API_KEY=your_key`
4. Railway auto-detects and deploys via `railway.toml`
5. Add the live URL to this README
